# BUG-001: `pytest tests/ -v --tb=short` fails without manual PYTHONPATH

## Status: CLOSED — FIXED (2026-04-02)

`pytest.ini` with `pythonpath = .` was added. Bare `pytest tests/ -v --tb=short` now passes
(7/7) without any manual environment setup.

---

## Title
Tests fail out-of-the-box with `ModuleNotFoundError: No module named 'app'` unless `PYTHONPATH` is set manually.

## Environment
- Python 3.11
- pytest 9.0.2
- Windows / PowerShell (and likely any OS without package install)

## Steps to Reproduce
```
cd c:\pars
pytest tests/ -v --tb=short
```

## Expected
Tests collect and run successfully; 7 passed.

## Actual
```
ImportError while loading conftest 'C:\pars\tests\conftest.py'.
tests\conftest.py:9: in <module>
    from app.db import Base, create_session_factory
E   ModuleNotFoundError: No module named 'app'
```
Exit code 4 (collection error).

## Root Cause
There is no `pytest.ini`, `setup.cfg`, or `pyproject.toml` setting `pythonpath = .` (or equivalent), and the `app` package is not installed as an editable package. Without `PYTHONPATH=c:\pars` the import fails.

## Impact
**The project's hard gate command does not pass clean**. Every CI run, every new developer checkout, and every agent running `pytest tests/ -v --tb=short` as documented in the rules will fail. This violates the testing rule requirement for CI parity.

## Severity / Priority
**High / P0** — blocks all automated testing.

## Fix Suggestion
Add `pytest.ini` (or `pyproject.toml` `[tool.pytest.ini_options]`):
```ini
[pytest]
pythonpath = .
```
or add a `setup.py` / install `app` as an editable package in requirements.
