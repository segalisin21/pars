# BUG-006: Username-only candidates recorded with misleading `error_code="user_not_found"`

## Status
CLOSED

## Title
In `run_invite`, when a candidate has no `tg_user_id`, the code records an `InviteAttempt` with `error_code="user_not_found"`. This error code is defined (REPORT.md, DESIGN.md) as the Telegram-level error when a real invite attempt fails because the account was deleted. It does not mean the same as "we have no Telegram ID for this candidate".

## Environment
- `app/services.py` — `run_invite()`, lines 191-203

## Steps to Reproduce
1. Collect a candidate with `tg_user_id=None, username="alice"`.
2. Start an invite run.
3. Inspect `InviteAttempt.error_code` for alice's attempt.

## Expected
A distinct `error_code` such as `"no_tg_id"` or `"username_only"` to differentiate "we can't invite because we lack an ID" from "Telegram says user doesn't exist".

## Actual
```python
# services.py lines 191-203
if cand.tg_user_id is None:
    skipped += 1
    db.add(InviteAttempt(
        ...
        status="skipped",
        error_code="user_not_found",   # ← wrong code
    ))
```

Operators or automated tooling reading `error_code="user_not_found"` will incorrectly infer the user account no longer exists (a permanent hard failure), rather than "we may be able to invite them once we obtain their tg_user_id from another source".

## Impact
Incorrect suppression logic could be built on this code. The operator dashboard would display "User not found" for username-only candidates, which is misleading.

## Severity / Priority
**Low / P3** — misleading metadata; no data loss but affects operator trust and potential future suppression automation.

## Fix Suggestion
Use a dedicated error code:
```python
error_code="no_tg_id"
```
And document `no_tg_id` in REPORT.md's error codes section.

## Resolution
Implemented a dedicated code: `missing_tg_user_id` and documented it in `docs/REPORT.md`.
