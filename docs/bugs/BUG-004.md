# BUG-004: `db.rollback()` in `upsert_candidate` rolls back the entire transaction, losing `CollectRun`

## Status: CLOSED — FIXED (2026-04-02)

`upsert_candidate()` now uses `with db.begin_nested():` (a SQLAlchemy savepoint) around
`db.flush()`. On `IntegrityError` only the savepoint is rolled back; the outer session
(including the `CollectRun` row) is unaffected. A re-query then fetches the existing
candidate and returns it.

---

## Title
When an `IntegrityError` is raised during candidate insertion (e.g. race on `uq_candidate_tg_user_id` or `uq_candidate_username`), `upsert_candidate` calls `db.rollback()`. This rolls back **all** pending ORM work in the session, including the `CollectRun` row that was already flushed earlier in `run_collect`. The subsequent `db.commit()` and `db.refresh(run)` in the endpoint operate on a detached/invalid object.

## Environment
- `app/services.py` — `upsert_candidate()`, `run_collect()`
- `app/main.py` — `start_collect_run()`

## Steps to Reproduce
1. Pre-populate the DB with a `CandidateUser(tg_user_id=1, username="alice")`.
2. Configure a source whose participants include `TgUser(tg_user_id=None, username="alice")` (same username, no tg_user_id — dedup path via username lookup will succeed) **and** a second user `TgUser(tg_user_id=1, username=None)` (tg_user_id match also succeeds).
3. Alternatively: trigger a concurrent duplicate write to force IntegrityError on `db.flush()`.
4. POST `/collect-runs` and observe.

## Expected
The `IntegrityError` fallback fetches the existing candidate and continues. The `CollectRun` row remains intact and is committed at the end.

## Actual
`db.rollback()` in `upsert_candidate` (line 65 of `services.py`) reverts the entire session:
- The `CollectRun` inserted at the start of `run_collect` is rolled back.
- `run.id` becomes stale; `db.refresh(run)` raises `InvalidRequestError` or silently returns wrong data.
- The collect run is lost from the database.

```python
# services.py upsert_candidate — the rollback scope is too wide
try:
    db.flush()
    return candidate
except IntegrityError:
    db.rollback()   # ← rolls back CollectRun too
    ...
```

## Impact
Data integrity loss: collect runs silently vanish when any candidate causes a dedup IntegrityError. The API returns a stale/incorrect CollectRunOut to the caller.

## Severity / Priority
**Medium / P2** — data integrity issue triggered in real usage when duplicate participants appear across sources.

## Fix Suggestion
Use a savepoint (`db.begin_nested()`) to isolate the candidate flush:
```python
sp = db.begin_nested()
try:
    db.flush()
    sp.commit()
    return candidate
except IntegrityError:
    sp.rollback()   # only reverts the candidate row; CollectRun survives
    ...
```
